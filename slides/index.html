The problem

The agent was not the unpredictable part.

The unchecked ambiguity was.

Meaning drifted“complete”, “secure”, and “end-to-end” had weaker interpretations.
Work driftedThe interesting domain model displaced the boring HTTP wiring.
Evidence driftedA green subset of tests was mistaken for a working system.
02

The failures were not random. They were permitted by ambiguity in the plan, task scope, and validation language.

The useful question is not “How do I make the model smarter?” It is “Where can the model reinterpret the contract without being stopped?”

07

The spec is intentionally implementation-agnostic but highly observable. It contains behaviors, explicit assumptions, state tables, use cases, edge cases, and copied normative data.

Every allowed lifecycle transition is named, and every unlisted transition is refused with no side effect.

The five normative data groups are accounts, opening hours, veterinarian schedules, exceptions, and configuration defaults.

Criteria are written in EARS forms: ubiquitous, event-driven, state-driven, unwanted behavior, and optional feature.

Traceability is two-way: every behavior is covered by at least one criterion, and every criterion names its source behavior and use-case flow.

The missing gate

The spec can pass while the plan is impossible.

ORIGINAL PIPELINE spec review → tasks → execute

No one asked whether the union of phase artifacts could perform the walkthrough.

Result: phase 1 planned templates and security—but no controller artifact.
IMPROVED PIPELINE spec review → tasks → plan review → execute

Check reachability, exact paths, route ownership, coverage, task shape, and skeleton order.

Re-plan review: 5 blockers + 4 majors → fixed → PASS.
14

The first plan went straight from generation to execution. That allowed a walking-skeleton phase with no controller artifact.

The new plan-review mode asks the decisive question: if you take the union of all artifacts in the phase, can you perform every checkpoint step and URL?

After the re-plan, round one still found five blockers and four majors. Fixing those before execution was cheaper than finding them at a checkpoint.

Fix · communication contract

Model failure became a domain outcome,
not a hanging request.

FailureAdapter policyRequest outcome
Malformed structured outputretry onceWith staff · reason recorded
Read timeoutdo not retry transportWith staff · “model timeout”
I/O / connection failuredo not retry transportWith staff · “model transport failure”
withTimeouts(10s, ${scheduling.ai.timeout:60s})
catch (ModelUnavailableException ex) {
  applyModelUnavailable(id, ex.getMessage(), actor);
}
Diagnosable:requestId · model · prompt version · attempt · raw response before typed conversion
23

The adapter contract distinguishes response failures from transport failures. Malformed structured output is retried exactly once. Timeouts and I/O failures are not retried and are mapped to stable domain reasons.

AsyncInterpretationService catches ModelUnavailableException and moves the request to With staff in a fresh state-checked transaction. The user is not left on an interpreting page forever.

The RestClient has a fixed 10-second connect timeout and a configurable read timeout, default 60 seconds. Contract tests assert both the exception mapping and the downstream request state/event reason.

Later instrumentation added SimpleLoggerAdvisor plus request-scoped logs of model, attempt, prompt, raw response, and mapped output.

Postmortem

The failure was permitted at three layers.

01 · PLAN

A hole in the artifact map

No controller artifact. Checkpoint criteria contradicted task validation. Large tasks hid scope.

02 · EXECUTOR

The model optimized for interest

Built solver internals ahead of HTTP wiring. Renamed tests. Reinterpreted proof. Never raised a blocker.

03 · PROCESS

Self-certification arrived first

No plan review. No mechanical definition of complete. Independent evidence came after ~6.5k lines.

Plan ambiguity+agent discretion+late verification=expensive convergence
24

The executor did not simply ignore a perfect plan. The plan omitted the HTTP surface and allowed conflicting readings.

But the process also failed to stop predictable executor behavior: batching, building ahead, silent artifact renames, weaker validations, and workarounds instead of blockers.

The takeaway

The spec is not a document.
It is the control system.

Clarify meaninggrill → behaviors → criteria
→
Constrain workrules → exact tasks → commits
→
Demand evidenceclosure → runtime → convergence
↺

Make decisions durable. Chat is transient; artifacts are inspectable.

Make “complete” mechanical. The agent should not grade its own interpretation.

Make stopping legitimate. A blocker is cheaper than a clever workaround.

Version the process. Let failures improve the skills that produce the next result.

Reliable AI development is not less iteration. It is iteration with memory, boundaries, and proof.
33

The durable insight is the closed loop. The same evidence that revises the implementation can revise the task plan, the spec, and the skills themselves.

This gives agents freedom inside a small, explicit task while taking away the freedom to silently redefine success.
